# Bootstrap Pre-Sales Quick Start

**Flip zero capital into funded pilot through customer pre-orders.**

---

## THE PITCH (One-Liner)

"We validate WTP with real money, not surveys. Customers fund the pilot."

---

## THE MATH

### Cost Comparison

| Path                                             | Time    | Cost    | Outcome         |
| ------------------------------------------------ | ------- | ------- | --------------- |
| **Old:** WTP survey → Decision → Pilot           | 5 weeks | $8-15k  | Maybe viable?   |
| **New:** Landing page → Ads → Pre-orders → Pilot | 2 weeks | $0.5-1k | Capital in hand |

### Deposit Mechanics

- Test ad spend: **$300-500**
- Expected leads from $500: **8-15 leads**
- Expected conversions: **1-2 deposits**
- Scale to **$2-3k spend → 50+ leads → $5-10k deposits**

### Where Deposits Go

- **Phase 1 (Ad test):** $300 spend = 8-15 leads
- **Phase 2 (Scale ads):** $2k more spend = 50+ leads = $5k+ deposits
- **Phase 3 (Installations):** Deposits → Battery cost + installation labor + permits

**By Week 6:** First customer installations paid for, revenue (lease payments) starting

---

## THE SEQUENCE

### Week 1: Build & Launch

- Carrd landing page (2 hours)
- 3 ad creatives on Canva (1 hour)
- Facebook/Stripe accounts (1 hour)
- Ad campaign: $500 test spend
- Expected: 8-15 leads

### Week 2: Validate & Scale

- Call all leads (phone closes)
- Collect 2-5 deposits
- Decision: Go (15+ leads) / Marginal (8-15 leads) / No-Go (<8 leads)
- If Go: Scale ads to $2-3k/week

### Week 3-4: Lead Generation + Partnerships

- Run higher-budget ads
- Collect 20-50 deposits ($5-15k)
- Recruit 1-2 installer partners
- Begin Phase 3 (installation prep)

### Week 5-6: First Installations

- Install first 3-5 customers from deposits
- Track satisfaction, uptime, activation during outages
- Collect testimonials
- Feed testimonials back into ads

## CRITICAL SUCCESS FACTORS

| Factor                   | Threshold         | Action                              |
| ------------------------ | ----------------- | ----------------------------------- |
| **CPL (Cost Per Lead)**  | <$35              | If >$50 by Day 3, pause             |
| **Form completion rate** | >10% of clicks    | If <5%, creative isn't working      |
| **Deposit conversion**   | 1-2 from 10 leads | If 0 from 15 leads, messaging issue |
| **Call-to-deposit lag**  | 24 hours max      | If >48 hours, leads get cold        |

## FAQ

**Q: What if I don't get deposits?**  
A: You spent $500 instead of $8k. You learned the same thing faster and cheaper. Pivot to organic (Nextdoor) or test new messaging.

**Q: Can I run ads cheaper than $300-500?**  
A: Yes. Start with $200, see if you get 5+ leads. If CPL is <$50, scale. If CPL is >$50, pause and fix messaging.

**Q: What if people ask "Can I buy instead of lease?"**  
A: Yes, offer purchase option at $13,500 cash. Mention lease is better (zero risk, maintenance included). Track who wants to buy vs. lease.

**Q: Should I target multiple ZIPs at once?**  
A: No. Start with 91942 (Ramona, single ZIP). If successful, add 92026, 92084, 92021. Then expand.

**Q: What about installer partnerships?**  
A: Wait until Week 2. Once you have 20+ leads and deposits, you have proof-of-concept. Then pitch installers: "I bring you customers, you do the labor, 25% commission on lease."

## THE BIGGER PICTURE

This bootstrap model proves **three things simultaneously:**

1. **WTP is real** (customers pay deposits, not just survey questions)
2. **Geography works** (high-PSPS ZIPs show intent)
3. **Unit economics close** (if you acquire at $35 CAC and keep customer for 5 years → LTV $3,600, payback in 17 months)

Once you prove these three, you can:

- Raise capital for scale (Series Seed / angel: "I have 50 paying customers, $5k MRR")
- Recruit installers (they join a proven model, not a pitch)
- Expand to other high-PSPS areas (CA, TX, FL)
- Build governance layer (ARF) on top (management only works if model is sound)

**This is why ARF says:** "Model validity precedes governance validity." You're doing this backwards (correctly): prove the model first, then layer governance.
